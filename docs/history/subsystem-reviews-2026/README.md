# Subsystem reviews 2026

This folder holds five unrelated hardening and audit records written between **2026-06-14 and July 2026**, each covering a different BioRouter subsystem: desktop reliability, developer-extension background jobs, system prompts, the CLI's terminal UI, and agent tool discovery. All of this work happened and all of it is finished — every review closes with a verification record, four of the five shipped and were integrated into `main`, and the fifth (the system-prompt inventory) had its central recommendations implemented, which superseded three of its own six parts. The folder is kept for the record and for provenance, not as current guidance: read it to find out *why* a subsystem behaves the way it does, never to find out what it does today.

Come here when you are tracing the origin of a behavioural contract — why a malformed store update can no longer take down the desktop shell, why `search_modules` returns what it returns, why the reply loop stops retrying a permanent provider error — or when a commit message from June or July 2026 refers to one of these passes. Two boundaries are worth knowing before you read further. First, the similarly named [`agent-loop-review/subsystem-reviews/`](../agent-loop-review/subsystem-reviews/README.md) is a *different* collection: ten sub-reports that dissect the agent loop as part of one review campaign, whereas the five documents here are independent point-in-time passes over five unrelated subsystems. Second, if you want current behaviour rather than history, leave for the live folders — [`docs/desktop-ui/`](../../desktop-ui/README.md), [`docs/cli/`](../../cli/README.md), [`docs/extensions/`](../../extensions/README.md) and [`docs/agent-loop/`](../../agent-loop/README.md). For the system prompt specifically, the current truth is `crates/biorouter/src/prompts/system.md` itself.

## Documents

| Document | What it covers |
| --- | --- |
| [Desktop reliability defects — July 2026](desktop-reliability-defects.md) | One batch of nine desktop defects reported against the July 2026 build — startup crash, diverge, stream and provider errors, tool-call expansion, provider auto-detection, notifications and diagnostics — with root causes, the fixes that shipped, the durable behavioural contracts they establish, and the full verification record. Every defect was resolved and integrated into `main`. |
| [Developer extension background jobs — design record](developer-background-jobs-design.md) | The investigation, competitive survey and shipped design for background process supervision: why the agent could not watch a long-running command, how other agents solve it, and the `shell background` / `shell_output` / `shell_wait` / `shell_kill` contract built in response. Shipped 2026-06-14 in the developer extension; the prototype standalone `monitor` extension was removed. |
| [System-prompt inventory and gap analysis](system-prompt-inventory-and-gaps.md) | A complete inventory of every system prompt and runtime-injected instruction in BioRouter, benchmarked against ~30 published agent system prompts, and the assessment of which agentic-behaviour clauses `system.md` was missing. Written 2026-06-14; Parts 2, 4 and 5 are superseded by the shipped prompt, with one open item — the unrendered `biorouter_mode` / `is_autonomous` / `enable_subagents` template variables. Parts 1 and 6 remain useful as written. |
| [Terminal UI stability audit — July 2026](terminal-ui-stability.md) | An audit of whether the July 2026 desktop and provider hardening destabilized the CLI's interactive terminal UI, recording two fixes — a retry-budget correction for permanent provider errors and a narrow-terminal status layout fix — plus a live tmux verification matrix. Both findings were fixed in July 2026. |
| [Agent tool discovery hardening — July 2026](tool-discovery-hardening.md) | One hardening pass on code-execution tool discovery: why the agent spent five top-level tool calls finding a web-scrape tool for a simple request, the root causes in lazy module discovery, and the tightened `search_modules` / `read_module` contract that fixed it. Shipped in July 2026 and verified against a clean `main` checkout. |

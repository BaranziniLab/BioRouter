# Platform integration audit

This audit distinguishes what an idea requests, what Agent Drafter writes into
the manifest, what the isolated BioRouter runtime actually has installed, and
what a browser-driven runtime turn demonstrably exercises. A configured name is
not counted as a working integration by itself.

## Requests in the 100-idea corpus

Every idea has a `Platform integration` line. Mechanical keyword counts are:

| Requested integration | Specs mentioning it |
|---|---:|
| Knowledge base / KB | 85 / 100 |
| Skill | 57 / 100 |
| Model route | 67 / 100 |
| Workflow | 35 / 100 |
| Scientific figure | 29 / 100 |
| Extension | 10 / 100 |
| Export | 15 / 100 |
| Connector (explicit word) | 0 / 100 |

## What this isolated BioRouter runtime actually provides

The catalogs were queried through the same CLI/environment used by the apps.

| Capability | Available in `.br-testdrive/runtime` |
|---|---|
| Built-in extensions | `developer`, `computercontroller`, `autovisualiser`, `memory`, `tutorial`, `agent_drafter`, `knowledge` |
| External extensions | none |
| Connector-style external integrations | none configured |
| Installed runtime skills | none |
| Installed knowledge bases | none |

Apps SDK v2 has no separate `connectors` manifest field. Connector-like MCP
integrations would be represented as external extensions; none are installed in
this isolated run. Codex-side connectors are not BioRouter app-runtime
capabilities and are not credited here.

The user's global BioRouter profile exposes several general skills, but the
test contract keeps every persistent app/runtime file inside the worktree. Those
global skills are therefore not silently imported or credited to isolated apps.

## Configuration observed in Specs 001–016

| Manifest feature | Apps configuring it | Real status |
|---|---:|---|
| Any extension | 16 / 16 | Built-in names are real |
| `knowledge` extension | 15 / 16 | Real extension, but no installed KB payload |
| `autovisualiser` extension | 15 / 16 | Real built-in; UI/scientific rendering is available |
| One or more skill ids | 7 / 16 | All unavailable in the isolated skill catalog |
| Concrete `knowledge_base` id | 13 / 16 | All unavailable in the isolated KB catalog |
| Non-empty knowledge grant ids | 8 / 16 | All unavailable grants |
| Model routes | 6 / 16 | Structurally configured on the locked UCSF model; runtime route selection still needs per-app evidence |
| Workflows | 6 / 16 | Structurally configured; runtime execution still needs per-app evidence |

Runtime history shows attempted skill/knowledge use in Specs 001, 003, 004,
008, 010, and 011. Because the isolated catalogs are empty, these attempts do
not prove a working skill or grounded KB integration; several visibly failed or
returned insufficient data. No external connector has run.

## Corrective protocol from Spec 021 onward

The Agent Drafter order and static reviewer now receive the exact isolated
catalog:

- configure only the seven real built-in extensions;
- never invent external extension, connector, skill, or KB identifiers;
- when a requested skill/KB/connector is unavailable, leave ids unset (empty
  knowledge grants) and document the unmet requirement honestly;
- enable `knowledge` or `autovisualiser` only as real built-ins;
- require non-empty UCSF-locked `orchestration.routes` when the spec asks for
  model routes;
- require non-empty `orchestration.workflows` when the spec asks for workflows;
- require `autovisualiser` when the spec asks for scientific figures; and
- distinguish configured, available, and runtime-exercised status in every
  result instead of awarding credit for a manifest string.

Specs 001–020 are being re-audited under the stricter rules. Invalid skill/KB
claims will be removed only through Agent Drafter refinement, not by hand.
Exports remain deferred to the guide's final cross-app export phase and will not
be marked exercised before that phase runs.

## Per-app evidence fields

Each remaining per-app result will include:

| Field | Meaning |
|---|---|
| Requested | What the idea's Platform integration line asks for |
| Configured | Manifest extensions, skills, KB grants, routes, workflows |
| Available | Exact configured entries present in the isolated catalog |
| Exercised | Browser/session evidence that a real tool/route/workflow ran |
| Missing/blocked | Requested integration unavailable or configured falsely |

The machine-readable inventory is generated by
`scripts/agent-drafter-testdrive/audit_platform_integrations.py`.

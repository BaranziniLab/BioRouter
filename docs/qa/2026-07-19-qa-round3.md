## PRIMARY TARGET 1 — COMPACTION (R2-08 headline gap): **TRIGGERED & CLEAN**

Rounds 1-2 never reached compaction. Root cause pinned in source: at the default
`BIOROUTER_AUTO_COMPACT_THRESHOLD=0.8` on gpt-5.5's **1,050,000-token** window, the
trigger needs ~840 K tokens of *instantaneous* context — unreachable in a driver
session (round-2 peak was ~138 K cumulative). Compaction had **never** fired in the
whole DB (0 summary-marker messages historically) — confirming R2-08 was a reach
problem, not a defect.

Forced it by relaunching the daemon with `BIOROUTER_AUTO_COMPACT_THRESHOLD=0.003`
(≈3,150 tokens) + `BIOROUTER_COMPACT_KEEP_LAST_TURNS=1` (default is 4, which needs
>4 turns before any prefix is summarizable). Then drove two sessions to real
compaction events and checked every guarantee:

**Session A (`20260720_3`, no-tool recall test).** T1 established facts ("magic
numbers 111/222/333, sum 666, codeword ZEBRA-42"); T2 filler; T3 asked to recall
them "purely from memory, without re-reading". Result:
- DB: **2 summary-marker messages** inserted (`"summary of the earlier part of this conversation, which was condensed because a context limit was reached"`). Compaction fired.
- Summary body **contains the facts** (`content_json LIKE '%111%'` and `%ZEBRA-42%` both true) — the prefix was condensed, not dropped.
- Recall answer (verbatim): **"Magic numbers: 111, 222, 333 · Sum: 666 · Secret codeword: ZEBRA-42"** — fully correct, recalled from the summary, no re-read, no contradiction.
- UI shows a **"Compaction complete"** divider before the answer; the two summary messages are `agent_only` (hidden from the user), the original T1/T2 turns stay **user-visible** (`showsNoted`, `shows144`, `showsFactsPrompt`, `showsAnswer` all true).
- `total_tokens` collapsed **4707 → 186**; context meter reads "0% used"; cost $0.05.

**Session B (`20260720_1`, tool-heavy integrity test).** Reopened the earlier
"File sum setup" session that has **8 tool cards** (incl. red "Tool call failed"
cards + a subagent run). Sent one recall turn to trigger compaction (keep_last=1 →
turn-1 prefix summarized). Result:
- DB: **1 summary-marker** inserted → compaction fired on a tool-bearing prefix.
- **All 8 tool cards still render** in the UI after compaction (`toolCards` = 8 before AND after); facts (`666`, `fileA`) still shown. **No lost tool cards.**
- Recall answer: **"Sum: 666; directory: `/tmp/qa-r3-compact`"** — correct, from summary, no repeat of the file-creation work.
- `total_tokens` **7520 → 468**.

**compactionResult:** triggered in both sessions; **nothing degraded** — transcript
integrity preserved (old turns + all tool cards remain user-visible), agent recalls
condensed facts correctly with no repeat/contradiction, context+cost meters drop
sanely, `agent_only` summaries correctly hidden, `errs=0`. One edge observed under
the pathological threshold — see **R3-03** (double-summary stacking).

Mechanism verified in source (`crates/biorouter/src/context_mgmt/mod.rs`
`compact_messages_with_window`): the older prefix is kept in the transcript for the
user (`with_agent_invisible`) while an `agent_only` summary drives the model — the
integrity guarantee is by design.

## findings

| id | area / severity | symptom / repro / suspect |
|----|-----------------|---------------------------|
| **R3-01** | chat UI / **minor (cosmetic)** | **Rapid double-click on Send leaves a phantom duplicate user bubble.** The backend guard is correct — only ONE turn sends and persists (DB `count=1` for the marker; one assistant reply) — but the optimistic on-send bubble is appended twice and stays visible in the live transcript; it **clears on a full reload** (re-render from persisted state shows 1). Repro: `setcomposer` then `button.click(); button.click()` synchronously. A very fast human double-click reproduces it. Suspect: the composer's optimistic message-append on submit doesn't guard against a second synchronous submit before the send-state flips (`ui/desktop/src/components/BaseChat.tsx` / `hooks/useChatStream.ts` / `hooks/chatStreamStore.tsx`). |
| **R3-02** | chat / send-recovery / **low (edge)** | **"Model request failed / Provider not set" error card has NO Retry button** (unlike the retryable "Connection dropped" card), and it surfaces after a daemon is hard-restarted out-of-band mid-session (the renderer↔daemon provider handshake is lost, so subsequent requests carry no provider). A renderer reconnect/reload restores the session. Repro: kill the GUI's `biorouterd` mid-session, restart a bare daemon on the same port+secret, click Retry / send again. Suspect: session/provider registration is in-memory per daemon instance and not re-established on a bare reconnect; and the inline-error taxonomy treats a provider-config error as terminal-for-turn (`ui/desktop/src/components/conversation/ChatTurnError.tsx`, backend session-config plumbing). Arguably out of scope for `87a5744d` (which is about graceful display, achieved). |
| **R3-03** | context_mgmt / compaction / **info (edge, pathological config only)** | **Two summary-marker blocks stacked at one turn boundary** under `THRESHOLD=0.003` + `KEEP_LAST_TURNS=1` (session `20260720_3` has 2 summaries for 1 recall turn). Benign (recall still correct), and **not reproducible at the default 0.8 threshold**. Likely the eager (post-turn) path and the synchronous (top-of-reply) path both compacting when the threshold is far below steady-state context. Suspect: `run_eager_compaction` + the sync check in `agents/agent.rs` both firing (`crates/biorouter/src/context_mgmt/mod.rs`). |
| **R3-04** | artifacts / preview / **low (cosmetic)** | **Artifact panel surfaces a raw Node error for an assistant-mentioned nonexistent path.** After the model referenced `~/Documents/qa-r3-ordinary.txt` (never created, because the write was denied), the auto-opened preview showed the raw string `ENOENT: no such file or directory, stat '/Users/wanjun/Documents/qa-r3-ordinary.txt'` rather than a friendly "file not found". Suspect: mentioned-path preview error rendering in `ui/desktop/src/components/artifacts/ArtifactViewer.tsx` / `read-artifact-file` IPC in `main.ts`. |

Suspect: sidebar `New Session` handler always creates a tab (`ui/desktop/src/components/…` sidebar / tab manager). |

A quiet instrument for serious work.

BioRouter is calm, precise, dense, and trustworthy. This reference defines the visual language shared by the desktop interface, technical surfaces, and product identity.

Light + dark Token driven WCAG-aware
01 / Principles

The instrument stays quiet.

The interface should disappear behind the work. Hierarchy comes from spacing, type, surface, and a single accent—not decoration.

01

Calm before expressive

Reserve visual energy for actions, state changes, and information that alters a decision.

02

Dense, never cramped

Keep expert workflows compact while preserving a clear reading order and deliberate whitespace.

03

Colour is evidence

Use the accent for brand and action. Use status hues only when they carry state or meaning.

04

Structure over ornament

Prefer hairlines, flat surfaces, and alignment. Elevate only when one surface truly floats above another.

05

One answer per pattern

Buttons, rows, tabs, focus, and overlays follow one shared grammar across every workflow.

06

Technical by nature

Code, terminal output, identifiers, and aligned numerals use the same purpose-built monospace layer.

07

Motion explains

Animation clarifies continuity and state. It never performs merely because a screen appeared.

08

Access is structural

Contrast, keyboard order, names, motion preferences, and forced-colour behavior are part of the component.

One accent

  • Use accent fill for the primary action in a region.
  • Use the accent bar for active navigation and tab indicators.
  • Use accent text for links and restrained emphasis.
  • Do not tint whole pages, cards, or decorative illustrations.

Status is authored per mode

  • Danger, success, warning, and info each have fill and text roles.
  • Light and dark values are tuned independently for contrast.
  • Pair colour with an icon and a plain-language label.
  • Never use status colours as alternate brand accents.

11 / Accessibility

Accessible by construction.

Every pattern must remain understandable without hue, pointer precision, animation, or perfect vision. Accessibility behavior belongs in the shared component.

  • Body text clears 4.5:1; large text and essential graphics clear 3:1.
  • Every action has an accessible name that describes its effect.
  • Keyboard order follows the visual and reading order.
  • Focus remains visible; stronger OS contrast preferences receive a neutral ring.
  • Status pairs colour with text, shape, or an icon.
  • Errors identify the field, explain the condition, and offer recovery.
  • Dialogs trap focus, close predictably, and return focus to their trigger.
  • Tooltips supplement labels; they never contain required interactive content.
  • Reduced-motion preference removes nonessential movement globally.
  • Tables use headers, aligned data, and tabular numerals where comparison matters.
  • Touch and pointer targets preserve adequate spacing even in dense views.
  • Light and dark modes receive equal accessibility review.

# v1.89.0 verification log

> **What this is.** The running record of how v1.89.0 was verified before release: what was
> tested, how, what broke, what was fixed, and what could not be tested here. Written as the
> work happened, not reconstructed afterwards.
> **Status:** Current — the release is being built and verified; it is **not** published.
> **Audience:** Anyone deciding whether this build is fit to ship, or diagnosing something it missed.

## Ground rules for this pass

- **Model.** Every verification that drives the agent uses **`versa_azure` / `gpt-5.5-2026-04-24`**
  (UCSF Versa GPT). No Anthropic model is used for verification — cost. Any run that reaches a
  different provider is void and must be repeated.
- **Config is sandboxed.** Driving the GUI uses a throwaway `XDG_CONFIG_HOME`. Launching the dev
  GUI has previously wiped `~/.config/biorouter`, and the user's real config holds live provider
  keys and knowledge bases.
- **Never drive the user's running app.** A packaged copy or a dev build only.
- **Real input, not synthetic.** `CDP Input.dispatchMouseEvent` bypasses the macOS window server
  and reports success regardless, so it cannot test anything involving drag regions, window
  moves, or tear-off. Those need `CGEventPost`. CDP is for *reading* state and screenshots.
- **A claim without a reproduction is a hypothesis** and is labelled one here.

## Findings

Numbered `F-nn`. Each records how it was found, because the *method* is the reusable part.

### F-01 — one cosmetic edit hid 2,443 test results (fixed)

`privacy::visibility::tests::the_matrix_has_production_callers` cuts
`workspace_extension.rs` at its `#[cfg(test)] mod tests` to scan only production text. A
workspace change made that module `pub(crate)`, the scan pinned the exact string
`"#[cfg(test)]\nmod tests {"`, stopped matching, and **panicked** — taking the entire
`biorouter` test binary down before any other test ran. Cargo then halted, so no other
workspace binary ran either.

The lane that made the change ran only its own two modules (98 tests) and never saw it.

**Fixed** by stepping over an optional visibility modifier instead of pinning one spelling. The
test's negative control — which proves the cut actually removed the test module — is what
establishes correctness, and it works for any spelling.

**The lesson is not "update both scans".** It is that a guard which *panics* rather than fails
takes its whole binary with it, so an unrelated edit can silently delete an entire suite's
coverage while CI still shows one red line.

### F-02 — `GET /diagnostics/{session_id}` returns a full private transcript, ungated (open)

`crates/biorouter-server/src/routes/status.rs` contains **zero** `session_reach` calls, while
`routes/session.rs` — whose two routes return *the same bytes* — has three. The diagnostics
route reaches `generate_diagnostics` → `export_session` → the full message list, written into
`session.json` inside the returned zip.

`session_reach.rs`'s own header says of the gated sibling: *"an unguarded sibling of a guarded
read is the defect this campaign keeps shipping."* This is another one. The manual test
checklist covers `/export` and `/events` and omits this route too.

Not covered by the DR-17/AR-11 ruling: that ruling accepts the daemon cannot *authenticate* a
local caller, whereas the reach gate keys on *capability*, a different axis.

### F-03 — the session-store capability is guarded at one door of three (open)

`SessionStoreInspector` is registered only at `agents/agent.rs`. The directly analogous
`global_memory` capability is guarded at three places — the inspector chain, `POST
/agent/call_tool`, and tool calls made from inside `execute_code` — plus an MCP-side barrier. A
literal store path in script text is caught; a runtime-assembled one is not, which is the exact
walk-past that made the global-memory boundary refusals necessary.

The lane that built the inspector declared this openly in its module header. No lane picked it up.

### F-04 — `rustlock.sh` silently no-ops, so some "verified builds" verified nothing (open)

The lock script runs `"$@"` with no PATH setup, and `cargo` is not on the agent shell's PATH, so
it exits 127 with `cargo: command not found`. Piping to `tail` then hides it. **Any lane that
reported a green build through that harness reported nothing.** Every build claim made via the
lock needs re-running with `PATH="$PWD/bin:$PATH"`.

### F-05 — two gated routes have no test at all (open)

Of the seven routes on `session_reach.rs`'s gated list, four are pinned by the ordering census
and five by the HTTP bypass tests. `/sessions/{id}/export` and `/sessions/{id}/events` have
neither. **Deleting either gate today fails nothing.**

### F-06 — `SessionListView` "flake" was a real product bug (FIXED)

Two tests failed when their file ran whole and passed when siblings were skipped. Bisection
disproved two hypotheses — a leaked mock implementation surviving `clearAllMocks`, and pollution
from the neighbouring shared-cache tests — and the repo's own `src/test/timeouts.ts` warns this
symptom "was misdiagnosed as [machine contention] more than once."

It was neither. **`SessionItem` was declared inside `SessionListView`'s render body.** React
compares element types by identity, so every parent render produced a *new type*: React unmounted
every row and mounted a replacement, discarding each row's DOM node. `React.memo` cannot help —
memo compares props, and a fresh type never gets that far.

A `MutationObserver` probe showed the row being replaced 8 ms after mount, so the node the test
held was already `isConnected=false` and `fireEvent.click` never reached React's delegated
listener. Running alone, the same replacement landed ~1 ms *after* the query resolved, which is
the entire difference between pass and fail. **Load only moved where the replacement landed; the
defect that made a re-render fatal was the unstable type.** The same cause explained the second
file, proven by an old-vs-new component experiment.

So the "flake" was the messenger: in the shipped app, every re-render of the session list
destroyed and rebuilt every row's DOM.

Fixed by moving `SessionItem` to module scope and making `setSessionRefs` a stable `useCallback`.
The workarounds it had forced into the tests — a settle-before-click, and a retry inside
`waitFor` — were removed, since a retry there would now mask a regression. No assertion was
changed, relaxed, skipped or retried. **20/20** repeated file runs; **5/5** full-suite runs at
2436/2436.

**The lesson:** an intermittent test failure is a hypothesis about the test. Here it was evidence
about the component, and two rounds of test-focused debugging (mine) missed it.

### F-07 — `privacy_toggle` hangs, so the Rust suite cannot complete (open, BLOCKING)

`crates/biorouter/tests/privacy_toggle.rs` never finishes.
`the_master_toggle_governs_every_gate_in_both_directions` runs **> 7 minutes alone with
`--exact`** — so it is neither lock contention between tests nor `--test-threads` related. A
full-workspace run reports 30 of 31 binaries (2633 passed, 0 failed) and then dies at this one.

Ruled out: guard reentrancy. The file's `set_privacy_tiers()` helper warns it is not reentrant
and "deadlocks rather than failing", but both hanging tests correctly `drop()` before
re-acquiring.

**Why it was invisible until now:** cargo stops at the first failing binary, and
`tests/providers.rs` was failing earlier on a live Anthropic call against an exhausted credit
balance — aborting every run *before* this binary. Removing the key made providers skip and
exposed it. **That is the second finding this week where a failure early in the sequence hid
everything behind it**, after F-01.

### F-08 — the test suite makes live, billed provider calls (open, by design)

`crates/biorouter/tests/providers.rs` fires a **real** request to every provider whose key is
present in the environment, and skips the rest. With `ANTHROPIC_API_KEY` set it billed Anthropic
and failed on an exhausted balance. Without it, all thirteen skip and the binary is 15/15 green.

Not a defect — but it means **`cargo test` costs money depending on the shell's environment**,
which is surprising, and it silently aborted every full-suite run for an unrelated reason. Every
run in this pass uses `env -u ANTHROPIC_API_KEY`.

## Guards added, so these classes cannot recur silently

- `every_test_binary_is_sandboxed` — fails, naming offenders, if any `crates/biorouter-server/tests/*.rs` omits the sandbox.
- `check-token-mirrors.mjs` (wired into `lint:check`) — fails if a colour token is declared and used by a utility but never mirrored, which renders `currentcolor`.
- `asserts_no_respellings` — fails if an enable-gate arm is re-derived instead of asked for.

Each was proven by mutation, not merely observed passing.

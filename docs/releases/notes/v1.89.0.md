# Biorouter v1.89.0 release notes

**Release date:** August 7, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

Biorouter v1.89.0 is a feature release built around one idea: **a conversation belongs to
you, not to the window it happens to be in.** A turn now survives a reload. A tab can be
dragged out into its own window and dragged back. A running session can be joined from the
terminal and steered while it works. Alongside that, the desktop interface has been rebuilt
on a single design system — one typeface, one spacing ladder, one set of colour roles.

Existing settings, sessions, providers, extensions, skills, workflows, applications,
knowledge bases, and usage history remain compatible.

## A turn now belongs to the session, not to the request

Reloading the window, or navigating away and back, used to kill whatever the agent was
doing. The turn was tied to the HTTP request that started it, so when the request went, so
did the work — tokens already spent, answer never delivered.

A turn is now owned by the session. Closing or reloading the window leaves it running, and
reopening the conversation **attaches to the turn in progress**: the transcript catches up
to where the agent has got to and then continues live, with no visible replay seam. If you
had started typing when the connection dropped, what you typed is still there — a rejoin
never eats a pending message.

One consequence worth knowing: because the stream is no longer request-scoped, cancelling
mid-turn now works from anywhere the session is open.

## Tabs can be torn off into their own window, and merged back

Drag a tab out of the strip and release it over empty space to open it as its own window.
Drag it onto another Biorouter window's tab strip to merge it in, with a caret showing
exactly where it will land. Escape during the drag cancels it.

Two behaviours are deliberate rather than accidental:

- **A window's only tab does not tear off.** Dragging it moves the window, which is what
  every other application does with a single-tab window.
- **A running turn no longer locks its tab in place.** Earlier designs blocked moving a tab
  with work in flight; since a turn now belongs to the session, the tab can move freely and
  the work follows it.

## The interface has one design system

The desktop app has been rebuilt on the Astryx design foundations. In practice:

- **Figtree** is the interface typeface, replacing the per-platform system stack, so the app
  looks the same on macOS, Windows and Linux.
- **Controls, dialogs, toasts, list views and the sidebar** now share one size scale, one
  radius vocabulary and one set of interaction tints, instead of each surface carrying its
  own. Dialogs, in particular, all now come from a single shell.
- **The sidebar rail is compact**, and the chat transcript is quieter — metadata no longer
  competes with the conversation.
- Three theme families ship as before (Parchment, Alma Mater, Roche Limit), and every one of
  them is audited for contrast on every build: **288 assertions across three families in
  both light and dark**.

## Joining and steering a session from the terminal

`biorouter session attach` joins a session that is already running — including one started
by the desktop app — and lets you steer it. `GET /sessions/running` publishes turn liveness
so a client can tell what is actually working from what is merely open.

In the desktop app, **History now nests subagent transcripts under the conversation that
spawned them**, including across date boundaries, and badges a run whose parent is not in
view rather than hiding it.

## Notable fixes

- **A cancelled worker turn is reported as an error, not as its answer.** An app whose
  worker was cancelled previously presented the partial result as if it were the response.
- **The CLI no longer mangles characters that straddle a socket read.** Multi-byte
  characters split across a read boundary were corrupted in `attach` output.
- **`attach --name` refuses an ambiguous name** instead of picking one of the matches.
- **An unreadable liveness answer is treated as unknown, not as "everything finished."**
- **Session grouping no longer drops rows it cannot nest**, and each History pane decides
  what it shows rather than inheriting another pane's fetch.
- **Model-authored session names are stripped of control characters.**
- **A dying window takes its drag caret with it**, and a merge acknowledgement can no longer
  leave one session showing in two windows.

## Verification

Every gate in the tree was run against this release: the frontend suite (**2155 tests across
225 files**), `tsc`, ESLint at `--max-warnings 0`, the theme generator check, the contrast
audit, the new design-token mirror check, and the full Rust workspace — `cargo check
--workspace --all-targets` with zero errors and zero warnings, plus the server and library
test suites.

Three guards were added during this cycle for defects that had shipped more than once each:
one that fails the build if any server test binary can reach a developer's real session
database, one that fails if a colour token is declared but never mirrored into the utility
layer (which silently renders the wrong colour), and one that fails if an enable-gate arm is
re-derived instead of asked for. Each was proven to fail against a deliberately broken
implementation rather than merely passing against a correct one.

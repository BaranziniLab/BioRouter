# Biorouter v1.89.1 release notes

**Release date:** August 19, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

Biorouter v1.89.1 is a patch release. It fixes the AWS Bedrock failure that could burn
half an hour of a session producing nothing, sizes short chat messages to their own
content instead of stretching them across the window, and finishes the terminology pass
so the app calls a chat a chat.

Existing settings, sessions, providers, extensions, skills, workflows, applications,
knowledge bases, and usage history remain compatible.

## Bedrock no longer loops instead of answering

On AWS Bedrock, a long answer could collapse into a loop of the agent restarting itself
and never finishing. One reported session ran 37 minutes, produced 31 restarts, and
never wrote the script that was asked for.

Two causes, both fixed.

**The output limit was never raised.** Biorouter did not send an output-length setting
at all, so Bedrock applied its own 4,096-token default no matter how much room the model
actually had — every long answer was cut off at the same place. Modern Claude models on
Bedrock now get a 64,000-token allowance, older and unrecognised ones keep the
conservative default, and a value you configure yourself is always used as-is.

That allowance is also **bounded by the model's context window**. Bedrock rejects a
request whose input plus output allowance exceeds the window, and automatic compaction
does not start until the chat is 80% full — which left a band on 200K-window models
where a request would be refused on a turn Biorouter believed was within budget. The
default allowance now fits inside the room compaction guarantees, so that band is closed
by construction.

**The model's reasoning was being invalidated.** Bedrock signs the reasoning attached to
a response, and Biorouter rebuilt the history in a way that broke the signature, so the
model could not simply carry on from where it stopped. Signed reasoning is now replayed
exactly as the provider emitted it for the rest of that reply, and a later ordinary turn
starts from a clean projection. Your stored transcript is unchanged and still shows
everything.

**When continuing genuinely cannot finish, it now stops.** Automatic continuation is
capped for the whole reply — twelve attempts, and only three that produce nothing you
can see — and a tool call no longer resets that budget. The instruction Biorouter sends
to continue is never shown as if you had typed it, which is what produced the 31 visible
restarts in the report. If the cap is reached, the turn ends with a clear message and
whatever was written is kept.

This applies to the UCSF Versa Bedrock endpoint as well as direct AWS.

## Short messages fit their text

A one-word message no longer stretches to the width of the timestamp row beneath it. The
bubble sizes to its content and stays right-aligned, with long messages, long unbroken
strings, attachments, resource chips, and the edit view all behaving as before.

## Chat, not session

The app now consistently calls a chat a **chat**. A new chat is called "New chat"
everywhere, and slash-command descriptions, the compaction notices, the context-limit
messages, and the CLI's own help text all match. Chats you named yourself are untouched,
including one you deliberately called "New Session".

"Session" is still used where it means the stored record, a session ID, a CLI command, an
API route, or a terminal session — those are not the same thing as the chat you are
reading.

# Biorouter v1.89.2 release notes

**Release date:** August 20, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

Biorouter v1.89.2 is a patch by version number and a substantial one by content: more than 120
commits across four areas that were each visibly incomplete in v1.89.1.

You can now run Biorouter on the **Claude and ChatGPT subscriptions you already pay for**, through
your own installed `claude` and `codex` commands, with no API key — and, unlike a bare CLI, the
child agent can call Biorouter's own tools, because they are handed to it over a private MCP
bridge that Biorouter serves and polices. Knowledge bases move onto a **real format**: the Open
Knowledge Format, with a strict biomedical profile, typed edges, and a graph you can inspect. The
desktop app **stops freezing at launch**. And you can finally **generate diagnostics from a private
chat**, which is the whole point of diagnostics for anyone whose work is private.

Existing settings, sessions, providers, extensions, skills, workflows, applications, knowledge
bases and usage history remain compatible. Knowledge bases created before this release keep
working and keep their existing layout.

## Use the subscription you already have

**Claude Code** and **Codex** are now Biorouter providers. They use the subscription you are
already signed in to, through the CLI you already installed, and they need no API key. Pick them
like any other provider; an onboarding card takes a fresh machine from nothing to a working setup,
reporting what it found — whether the command is installed, whether you are signed in, and which
plan you are on.

**They are not a chat window wrapped in a subprocess.** A coding agent running inside Biorouter
gets Biorouter's tools — your extensions, your knowledge bases, the developer tools — over a
private MCP bridge. Biorouter serves that bridge, and every call the child makes comes back
through Biorouter's own permission checks, tool inspectors, `PreToolUse` hooks and path jail
before anything runs.

**The two providers differ here, and the difference is worth knowing.** With Claude Code the
child's own built-in tools are turned off outright, so the only tools it has are the ones this
chat grants it over the bridge. Codex's `exec` and `apply_patch` cannot be removed, so they
remain: they are confined to a read-only sandbox and the child is instructed not to use them, but
that confinement stops writes only. Reads and read-only commands it runs that way do not pass
through Biorouter's inspectors, permission mode, `.biorouterignore` or vault the way a bridged
call does.

**One known gap, stated plainly because it affects which provider to choose.** Claude Code is
launched with a flag that makes Biorouter's bridge the only MCP server the child can see. Codex has
no equivalent, and the configuration Biorouter sends is merged with the user's own
`~/.codex/config.toml` rather than replacing it — so MCP servers declared there are loaded into the
Codex child too, and their tools run outside Biorouter's inspectors, permission mode,
`.biorouterignore` and vault. If that matters for your work, use Claude Code. The fix needs a live
signed-in Codex to validate and will follow.

The bridge's credential is a per-turn nonce that never appears on a command line — Claude Code
reads it from a `0600` config file, Codex receives it in the handshake on its stdin — and it is
revoked the moment the turn ends. Several things that were wrong in the first
implementation are fixed here: a bridged call now resolves `{{vault:NAME}}` secrets, is jailed by
its own session's permission mode, receives the rewrite a `PreToolUse` hook asked for, and is
reachable by the turn's Stop button. **Cancelling now reaps the vendor process** instead of
leaving it running.

A lead/worker pair gets a bridge when *either* half is a coding agent, which matters because the
worker runs most of the turns — previously the tool-less child was the ordinary case rather than
the corner one. A Codex account that bills per token is refused at the start of the turn rather
than quietly charged, and a Codex turn that fails on an unknown model name now says so and lists
the names that work.

## Knowledge bases have a real format

Knowledge bases are now written in the **Open Knowledge Format (OKF v0.2)**, with **BioOKF v0.5**
as a strict biomedical profile: 28 page types, 35 link predicates, and every link required to name
its evidence. You choose the format when you create a base, and the chooser says plainly what each
one commits you to — general knowledge accepts anything and only reports broken links, while the
biomedical profile validates against the vocabulary and names the closest legal value when you
stray outside it. The format is fixed once a base is created, and the dialog says so.

The graph is **typed**: edges carry their predicate and their authority, and an inspector shows the
verdict behind each one. Two bases can be **merged**, with a dry run first; a merge is refused when
the two formats do not compose, and the refusal explains which pair failed.

Several data-visibility bugs are fixed. A page written over HTTP now **reaches the graph
immediately** rather than after the next unrelated rebuild. Aborting a transaction no longer drops
the newest pages from the graph. Retracted papers and source credibility are recognised on every
layout rather than only the pre-OKF one. And **renaming a base no longer strips the record of which
institutions own it** — a privacy defect, since that record is what stops another institution's
model reading it.

Ingest stops offering models that cannot do the job: a coding agent only receives tools inside a
chat, so a digest run on one would finish having written nothing. The picker now leaves them out
and says why. An ingest that got no tools reports that, instead of looking like a model that
refused to work.

## The app stops freezing at launch

The startup freeze is fixed at its cause: **no synchronous subprocess spawns or bulk filesystem
copies run on the Electron main thread during launch any more.** The bundled MinGit copy on Windows was the largest offender, blocking
before the window even existed. A watchdog now reports a blocked main thread rather than leaving
you to guess, and the updater no longer heats the machine immediately after launch.

Smaller things that were wrong every day: **File ▸ New Window and ⌘N work again** — the menu item
had been calling an event emitter in a way that threw silently, so the menu simply lied. The
greeting **unrolls on the first frame** instead of appearing whole, vanishing, and unrolling a
second time. It is also announced to a screen reader as a sentence rather than letter by letter. A
**torn-off window opens in the project directory**, not in your home directory. Extension updates
that failed in the background used to do so silently, and now report. A failed dependency install
offers a "Debug with Biorouter" way out, and the untrusted text it quotes into that prompt is
fenced so it cannot smuggle instructions.

`biorouter doctor --fix` will now hand a failing prerequisite to Biorouter to repair.

## Diagnostics work on private chats

Generating a diagnostics report **used to fail on a private chat** — which meant that the people
most likely to hit a bug worth reporting were the people who could not report it. A private chat
now produces a bundle like any other, with a warning stating what the file contains and asking you
to read it before sending it anywhere. A collection that loses one file now still produces the
report, with a note recording what was missed, rather than failing outright. The keyless refusal
names a command that actually exists on the machine reading it.

## Fixes

- The store removal in the CLI waits off the runtime thread rather than parking it, which is what
  the Windows test flake actually was. An earlier attempt that enlarged the timeout was wrong; the
  budget has since been brought back down, because a long wait held under a process-global lock
  serialises the whole test binary.
- A non-ASCII byte in a subprocess's stderr tail could panic the app server's reader.
- The tool bridge is exempt from the secret-key middleware, since its nonce is its credential.
- An external backend can hold a user-action key and stops losing one.
- The four knowledge skills no longer offer a Delete control that silently reverted.
- The nightly cross-build now boots what users actually install rather than a bare image, so a
  missing runtime dependency fails the nightly instead of the user's machine.

## Verification

Beyond the test suites, this release was exercised in a running build: the greeting measured
frame by frame across a real mount, ⌘N driven through the actual menu, a real Claude Code turn
whose bridged tool call left a file on disk, that same call cancelled mid-run with the vendor
process confirmed reaped, the knowledge graph observed gaining nodes and edges the instant a page
was written over HTTP, and the private-chat diagnostics path taken end to end. That pass found one
bug that every unit test had missed and it is fixed here: the private-chat warning was reading a
classification captured before the chat became private, so it never appeared on a real private
chat.

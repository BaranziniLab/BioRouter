# Biorouter v1.89.3 release notes

**Release date:** August 22, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

v1.89.2 let you run Biorouter on the Claude and ChatGPT subscriptions you already pay for. It had
one conspicuous rough edge: the answer arrived **all at once**, minutes after you asked, and the
tools the coding agent used along the way were invisible — the work happened, but you could not
watch it happen.

v1.89.3 fixes exactly that. **Claude Code and Codex now stream**, and **every tool call the agent
makes appears as a card** with the same behaviour you get from an API provider: it shows up the
moment the call is made, turns green or red when it finishes, and expands to show precisely what
went in and what came back.

Existing settings, sessions, providers, extensions, skills, workflows, applications, knowledge
bases and usage history remain compatible. Nothing about how you install or sign in to the vendor
CLIs has changed.

## Watch the answer arrive

Both subscription providers previously ran the whole turn behind a spinner. They now ask their
CLI for a live stream and forward it as it comes: text appears as the model writes it, and the
reasoning that precedes it is no longer dead air.

Measured on a real turn: the first words reached the screen about seven seconds in, and the rest
followed over the next two — where before, nothing appeared until the turn was over.

One honest note on what to expect. Claude Code batches its output more coarsely than an API
provider does, so a one-line answer may still arrive in a single piece; a paragraph arrives in
several. That is the vendor's chunking, not Biorouter holding anything back.

## See what the agent actually did

The bigger change is that the agent's tool use is no longer invisible.

When Claude Code or Codex calls one of Biorouter's tools, the call now appears in the transcript
as an ordinary tool card — the same card, drawn by the same component, that every other provider
produces:

- a **pending card** appears as soon as the tool's name is known, with its arguments filling in;
- it **settles green or red** when the call finishes;
- it **expands** to show the exact arguments sent and the exact output returned.

This matters beyond convenience. These tools run on **Biorouter's** side of the bridge — behind its
inspectors, permission mode, `.biorouterignore`, vault and privacy gates — and until now you had no
way to see which ones ran or what they touched.

### Calls Biorouter did not police are labelled as such

Codex keeps two built-in tools that cannot be switched off; Biorouter confines them to a read-only
sandbox, but they run inside the child and never pass through Biorouter's gates. Those calls are
still shown — hiding them would be worse — and they carry a quiet note reading **"not gated by
Biorouter"**, so a command card never implies an approval that did not happen.

### What still is not possible

A bridged tool call that would need a person's approval is **refused** rather than pausing to ask.
The child has no channel to prompt through, so the turn cannot wait on you. The refusal is now at
least visible as a failed card naming the tool, instead of vanishing silently.

## Fixes found while building this

Verification turned up several defects that predate this release or would have shipped with it:

- **Lead/worker pairs kept rotating.** Making a pair report that it streams would have bypassed the
  accounting that advances the turn counter, so the worker model would never have been used again —
  silently, for every lead/worker user.
- **Codex approval replies now match the schema.** All five approval methods were being answered
  with a value none of them accept, in a shape two of them do not even define.
- **Codex usage is no longer misread.** Billed tokens are cumulative over a turn's model requests;
  context occupancy is not. Reading one for the other inflated the context gauge by roughly a full
  window per tool call.
- **An unrecognised Codex turn status is no longer reported as success**, which had made a status
  the build did not understand indistinguishable from a finished turn.
- **Cancelling a streaming turn reaps the child process.** Streaming moves the child into a
  background task, and without an explicit guard a cancelled turn would have left `claude` or
  `codex app-server` running detached — holding your credential and spending your quota on an
  answer nobody would read.

their platform from the table above. No migration runs and no configuration changes are required.

# Biorouter v1.89.4 release notes

**Release date:** August 23, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

v1.89.4 is about **seeing things**: the Knowledge section gets the interface rebuild its graph
always needed, generated figures render reliably and in one predictable place, and the composer
tells you it is working without the pulsing dot that said nothing.

Everything here is a fix or a refinement to a surface you already use. Existing settings,
sessions, providers, extensions, skills, workflows, applications, knowledge bases and usage
history remain compatible.

## The Knowledge section, rebuilt

The Knowledge view's graph and its surrounding furniture were designed around a bottom dock and a
fixed layout that stopped working as soon as the window changed size. This release replaces that
with a shell built on container queries and a real responsive ladder.

What changes when you open it:

- **An all-circle canvas.** Node shape as a data channel was proposed, prototyped, measured and
  then **removed** — it did not survive its own evaluation. The graph now distinguishes nodes by a
  re-solved lightness-band palette and hollow provenance marks instead. The withdrawal is recorded
  rather than quietly dropped, because a design decision that was reversed is worth more written
  down than forgotten.
- **The legend leaves the bottom dock** for a rail it shares with the inspector, and can be
  dismissed. It no longer overlaps the canvas at any window size — a guarantee that is now tested
  rather than assumed.
- **Filters that read as filters**, instead of controls you had to learn.
- **A sources rail that stops scrolling at rest**, so the panel is still where you left it.
- **Keyboard traversal** through the graph, and an honest graph fit that does not pretend the
  viewport is bigger than it is.
- **A de-crowded knowledge-base manager.**

The specification and a browser-viewable studio ship with the code in
[`docs/knowledge-base/knowledge-ui-redesign/`](../../knowledge-base/knowledge-ui-redesign/README.md),
including eight decision records.

## Figures render, and render in one place

Two separate defects meant Auto Visualiser figures could silently fail.

**Mermaid diagrams never loaded their library in the desktop app.** The app runs figures in CDN
mode by default, and the main process re-inlines a fixed list of CDN assets before applying a
network-denying policy — a list Mermaid was missing from. Every Mermaid diagram therefore failed
with "Mermaid library failed to load". Mermaid is now emitted in a form the inliner handles, and
the CDN→inline contract is guarded from both sides so the two halves cannot drift apart again.

**Standalone artifact surfaces ran no JavaScript at all.** A figure opened through "open in
window", "open in browser", or the headless renderer's tab was an empty card with no error message
— because the error handler is a script too, and it was blocked along with everything else. A
`srcdoc` document enforces its embedder's policy as well as its own, so the wrapper's
`default-src 'none'` was governing the figure rather than fencing it. The wrapper policy now
scopes to the wrapper.

**One display surface.** A generated figure now opens in the artifact side panel on every
transcript, rather than rendering inline in some views and in a proxy-backed frame in others. The
`/mcp-ui-proxy` route existed only to serve that second path and has been removed.

## The composer says when it is working

The pulsing dot has been replaced by a working edge on the composer itself. It reads as activity
without asking you to interpret a blinking circle, and it does not compete with the answer arriving
above it.

## Upgrading

macOS users on v1.89.3 can take the in-app update. Everyone else should download the artifact for
their platform from the table above. No migration runs and no configuration changes are required.

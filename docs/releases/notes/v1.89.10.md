# Biorouter v1.89.10 release notes

**Release date:** August 28, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

v1.89.10 repairs the coding-agent bridge used for delegated Knowledge work. A
Codex or Claude Code parent can now create a bounded child that ingests a source,
queries the resulting knowledge base, and lints it through Biorouter's audited
tools. The child sees the tool profile it actually receives, while developer,
computer-control, and raw knowledge-base write surfaces remain unavailable.

## Delegated Knowledge work is truthful and complete

Coding-agent children receive Biorouter tools over a scoped bridge rather than
through the provider's ordinary request payload. Two mismatches made that path
look broader than it was and then blocked the one high-level operation needed to
complete an ingest:

- An omitted extension list gave the child a full Knowledge profile even though
  the bridge exposed only its bounded read surface. Explicit requests for
  Developer or Computer Controller were silently narrowed instead of rejected.
- The transactional `platform__ingest_source` tool was absent from the bridge,
  and the Codex and Claude Code providers still declared themselves unable to
  drive a Knowledge tool loop after the provider-driven bridge had landed.

The child profile is now derived from the exact bridge grant. Unsupported explicit
extension requests fail before a child is created, so a model cannot mistake a
silently narrowed run for the one it requested. The high-level ingest tool is
available only while the bundled Knowledge extension remains live and trusted;
raw page writes, developer shell access, and computer control remain blocked.

For Codex and Claude Code, Knowledge macros now use the provider-driven bridge to
the transaction-bound dispatcher. Executed calls are returned as records and are
not dispatched a second time. Providers with no request-tool or bridge mechanism
are still refused before any source is touched, and Biorouter never substitutes a
different provider or billing path.

## Verification

The repaired flow was exercised in a self-spawned development build with keyring
storage disabled. A real Codex-backed parent created one child, which used the
high-level ingest operation, found the curated marker through search, and returned
a successful lint report. The desktop Knowledge view then rendered the curated
pages, links, and graph. No password or biometric prompt was used for that run.

The release source also passes the complete Rust workspace, all desktop tests, and
the repository's full `just check-everything` release gate, including schema,
version, brand, cross-build, registry, privacy, and accessibility checks.

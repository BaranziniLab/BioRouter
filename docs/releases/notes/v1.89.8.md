# Biorouter v1.89.8 release notes

**Release date:** August 27, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

v1.89.8 makes one capability genuinely work and one settings surface honest. An agent can now
inject a prompt into **any** conversation it is allowed to see — not only a subagent it spawned —
and that prompt appears in the target chat's transcript live, whether that chat is mid-turn or
idle. The privacy tier is the only boundary that constrains this; being unrelated to the target no
longer is, and a write that crosses from a private conversation into a public one now discloses
itself before anything is delivered. Separately, the knowledge skills stop presenting themselves as
per-chat skills and become a single **Knowledge** context managed in Settings, so the skill counts
on the composer, in the Skills tab, and in what the model actually receives finally agree. It also repairs four providers — Versa Azure OpenAI, Versa Bedrock, Codex and Claude Code — each of which failed to start for a reason its own error message named incorrectly, and refreshes the Codex and Claude Code model lists.

## An agent can steer any conversation it can see

- `workspace_send_prompt` reaches any conversation the caller is permitted to see, in all three
  modes: `turn` starts a turn on an idle chat, `steer` injects into a running one mid-turn, and
  `note` appends context the target picks up on its next turn.
- The injected prompt now appears in the target chat's transcript **in real time**, with no reload,
  on all three paths. Each mode reaches the interface by a different route, and the note and turn
  paths previously reached it by none.
- Lineage is no longer a write boundary. Seeing a sibling conversation used to license reading it
  but not steering it; that restriction is retired.
- A delegating agent is offered the tool together with `workspace_list`, so it can discover which
  conversations exist and which are still running. `workspace_list` is a targeting surface as well
  as a discovery one, and the trade-off is stated in the pull request rather than left implicit.
- Guidance tells the model to inject only where it is genuinely necessary: it interrupts a
  conversation a person may be watching.

## The privacy boundary is the only boundary, and it now discloses itself

- A public-capability chat still cannot write into a private conversation, and a private
  conversation's title is still omitted from listings rather than redacted.
- A private-capability chat writing into a public one is permitted and **shows the payload first**:
  the first time a given caller/target pair crosses, an approval card names the target and quotes
  exactly what would be sent. Denying it delivers nothing and does not suppress the next request.
- That disclosure previously existed only as a design record, carried in the guard census as
  unwired. Widening the write rule is what made it load-bearing, so it was built rather than
  assumed.

## Knowledge skills become one Knowledge context

- The four built-in knowledge skills and `update-soul` are now a single **Knowledge** context,
  enabled or disabled in Settings rather than per chat.
- The composer's skill count, the Skills tab, and the skills the model actually receives now agree.
- Built-in skills can no longer be deleted from the Skills pane. Deleting one previously appeared
  to succeed and was silently rewritten on the next start.
- An existing installation migrates in place: user edits and supporting files are carried into the
  bundle rather than replaced, and a skill disabled machine-wide before the change stays disabled.

## Fixes

- **A chat working outside your home folder can preview the files it writes.**
  With a working directory such as `/ws/projects/…`, the preview panel refused
  files the session had just created — "Access denied: … is outside allowed
  directories" — because the folder you pointed the chat at was never an allowed
  root while your home folder always was. It is a root now, scoped to the window
  that owns it, and it does not admit sensitive locations: pointing a chat at
  `~/.ssh` still does not make it readable.
- **A `~/` in front of a path that was never under your home folder now resolves
  to the real file.** Models habitually write `~/` before a path; where the
  working directory is itself outside the home tree that produced a link to a
  file that never existed, while the tilde-free links in the same answer worked.
  The absolute reading is taken only when the home one does not exist, so no
  path that works today changes.
- Toasts expire again. `pauseOnFocusLoss` defaulted on, so a dismissal timer stopped whenever the
  window was not frontmost and notifications appeared to stick.
- Biorouter's own bundled extensions no longer announce themselves as newly installed on a first
  run.
- An injected message no longer makes an idle chat display a running turn.

## Providers

Four providers failed to start for reasons that had nothing to do with the credential or the
service, and each error named the wrong thing — so following its advice could not fix it.

- **Versa Azure OpenAI told users to install the Azure CLI.** The provider signs in with an API
  key, and the key was present and valid. But the code that read it discarded *why* a read failed,
  so "the store refused the read" became indistinguishable from "no key is configured" — and the
  fallback for the latter is the Azure CLI. Sign-in was silently re-routed through a tool the user
  had never installed, and the error named that tool. A failed read is now reported as one, and
  points at the credential store.
- **Versa Bedrock told users to re-enter a credential that was already correct.** Same discard,
  opposite advice needed: "add it in Settings" is right when a key is genuinely absent and actively
  misleading when the store refused to hand over a key that is there.
- **The Azure CLI was looked for only on the launching process's PATH.** A desktop app started from
  Finder inherits `/usr/bin:/bin:/usr/sbin:/sbin`, so a Homebrew `az` was invisible and the user was
  told to install what they already had. It is now resolved the way every other CLI-backed provider
  resolves its tool, and the message says where it looked.
- **Codex refused to start with `Unknown feature flag: skill_search`.** The app server is launched
  with feature flags, and a Codex build that does not recognise one exits rather than ignoring it —
  so a vendor CLI update broke the provider. Unrecognised flags are now dropped and the server
  respawned. If it exits during start-up anyway, the message says the server exited and includes its
  own output, instead of reporting a closed pipe.

Why a credential read fails at all is worth knowing, because it will happen again right after an
update: on macOS a Keychain grant is bound to the application's signature, so a newly installed or
re-signed build asks permission again. An unanswered prompt fails the read. Answer it with **Always
Allow**.

### Model catalogs

- **Codex** offers GPT-5.6 Sol, Terra and Luna alongside GPT-5.5, GPT-5.4, GPT-5.4 mini and the
  Codex Spark model. `gpt-5.3-codex` is retired: it was offered and does not exist, so selecting it
  could only fail.
- **Claude Code** offers Opus 5, Fable 5 and Sonnet 5 alongside Sonnet 4.6 and Haiku 4.5.
- Both providers now find a vendor CLI installed through a Node version manager (Volta, nvm, fnm,
  asdf) or Scoop, and wait a full minute for the child to start rather than five seconds — the
  earlier ceiling timed a cold process spawn and reported a working install as a failure.

### A 403 no longer leaks a request signature

A Bedrock error was rendered as roughly forty lines of Rust debug output. That rendering includes
the raw HTTP response, and the raw response carries the SigV4 `authorization` header — the
`Credential=` and `Signature=` values. Anyone reporting a 403 was pasting a live request signature
into wherever they pasted the error. The message is now the service's own text; a test asserts that
no transport material can reach it.

## Continuous integration

Several long-standing intermittent test failures were diagnosed and fixed. They share one root
cause worth naming: **a reader of process-global state that never took the guard its writers
correctly held.** In each case the writers were already correct, and adding a lock to them would
have changed nothing.

- `test (macos-latest)` could not save a Rust cache, because the cache is written only when a job
  succeeds and the job could not finish without one — so every run rebuilt the whole workspace from
  scratch. The cache is now written even on a red run.
- Feature-branch runs were each writing their own private caches, which no other branch can read,
  while evicting the shared ones. Saving is now confined to the default branch.
- The OS credential store is disabled across the test matrix; on a runner with no unlocked login
  keychain it blocked on an authorization prompt nothing was there to answer.
- Three child-process waits timed a process spawn against a five-second ceiling.
- The machine-wide memory-store tests resolved the configuration root twice and could match one
  resolution against the other, failing as though a shell command had reached the store.
- A shared test double consumed queued replies it could never return, so an unrelated test's frame
  could trip another test's assertion.
- A live import test pinned a third-party package version and failed when that project released.

### Known intermittents

Two test-harness races are known and not fixed in this release. Neither affects the shipped
application; both can make a continuous-integration run red and are safe to re-run.

- `subagent_handler::cancel_turn_on_the_child_stops_the_run_and_spares_the_parent` can observe a
  session id belonging to another test. Confirmed foreign: the module passes in isolation.
- `session::builder::close_ephemeral_store_removes_the_directory` can fail on Windows when the
  operating system has not released a file handle inside the retry budget.

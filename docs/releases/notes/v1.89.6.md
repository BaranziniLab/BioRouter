# Biorouter v1.89.6 release notes

**Release date:** August 24, 2026

**Repository:** [github.com/BaranziniLab/biorouter](https://github.com/BaranziniLab/biorouter)

v1.89.6 carries everything v1.89.5 was built for — **installing and delegating** — and adds the
one fix that made v1.89.5 unshippable.

**v1.89.5 was published and withdrawn the same day.** If you took it, please update: it contained
a defect that could make the whole window stop answering. v1.89.6 is that release with the defect
fixed. If you are coming from v1.89.4 or earlier, everything below is new to you.

Everything here is a fix or a refinement to a surface you already use. Existing settings,
sessions, providers, extensions, skills, workflows, applications, knowledge bases and usage
history remain compatible.

## The fix that made this release

On v1.89.5 the app could reach a state where **it looked completely normal and answered nothing**.
The model picker's "Select model" button did nothing when clicked, chat reported *"Backend
disconnected"*, provider model lists would not load, and the diagnostics bundle span at
"Generating…" forever. It was reported, accurately, as *"the Select Model button actually froze
without telling me why"*.

None of it was the backend, and none of it was any particular provider. The daemon was healthy
throughout — it answered a direct request in 129 ms while the window in front of it was inert.

The new extension-catalogue subscription could restart itself in a loop. Each restart asked the
daemon *"what has changed since the beginning?"*, which is a question the daemon answers instantly
rather than waiting on, so the answer restarted it again. A browser allows six connections to one
host; the loop claimed all six and never let go, and **every other request the window wanted to
make queued behind them and never ran**. Measured on an idle app, that was 18,923 requests in 50
seconds — about 126 catalogue polls per second — against 48 requests in 70 seconds once fixed.

Two things changed. The loop cannot restart itself any more, and it releases its connection when
it stops. And the model picker, which previously had no way to tell you any of this, now shows
**"Switching…"** while it works and writes the reason into the dialog when a switch does not
happen, instead of leaving a live-looking button and a notification in the far corner of the
screen.

**The separate headless download is gone, and nothing was lost with it.** Browser access is now a
command on the CLI you already install: `biorouter serve` starts the daemon, points it at the
built interface and prints a URL. The `biorouter-headless` binary and its Linux tarball were
retired in favour of it, taking the release from 11 published files to 10.

## Installing an extension stops interrogating you

Three things went wrong in the same flow, and all three are fixed.

- **The marketplace stopped asking for a file it already had.** Choosing an extension from BAAM
  walked you into the local file-drop step, as though you had not just picked the thing to
  install. The marketplace path now carries its own bundle through.
- **Credentials go to the keychain, not into the chat.** An extension that needs a passcode now
  raises a dialog the model cannot see. The value goes to the OS credential store; what comes
  back to the conversation is the *names* of the keys that were configured, never a value. A
  request that tries to answer a card with a value in it is refused, and an install that cannot
  authenticate is no longer registered in a half-working state.
- **A newly installed extension works in the chat you installed it from.** Its tools are
  available before the next model turn, instead of after a restart.

## Skills are packages, and the toggles are real

- A repository that contains several coordinated skills now **imports as one package** rather
  than being flattened into unrelated entries.
- There is **one skill catalog**, served by the daemon, that every surface reads — so a skill
  installed mid-conversation shows up without a reload.
- **Per-chat skill toggles now reach the chat.** They were previously UI-only: the switch moved
  and the agent never heard about it. When one of several toggles fails, only that one rolls
  back rather than the whole batch.
- **Settings, @-mentions and the workflow picker all read the same catalog**, so a skill cannot
  appear in one list and be missing from another.
- Importing from a real repository turned up **three defects the fixtures could not**, all fixed
  here: the fixtures were too well-formed to exercise them.

## A bridged tool call can ask a person, and wait

When Claude Code or Codex drives a Biorouter tool, that tool sometimes needs approval.

- **The approval dialog now appears, and the call resumes when you answer it.** Denial comes back
  to the child as an ordinary tool result rather than an error.
- **A slow call no longer dies at the child's default deadline.** Both vendors cut a bridged MCP
  call off well before Biorouter's own limit; a long-running call now survives to its real bound.
- **Knowledge macros run on the coding-agent providers**, and the denylist that used to keep them
  off is gone.

## Knowledge, conversations and the preview panel

- **Documents ingest into a knowledge base from a chat**, through the transactional macro, so a
  run that fails partway leaves no half-written pages.
- Auto mode **stopped treating a knowledge page write as a write to the filesystem root** when the
  page body happened to contain `split("/")`.
- **Delegation is structurally distinct from opening a chat**, so asking for a subagent can no
  longer produce an ordinary unparented conversation that merely looks like one.
- **Right-click a conversation** in History or the sidebar for chat actions, including Copy
  conversation ID.
- **The preview panel gained a real browser**, TIFF and HEIC decoding where each is honest, the
  ability to point at a region and send it to the chat, and a tool that lets the agent read what
  you are looking at.

## Local models pick the right model

The local model list was selecting the wrong entry — a hit-test problem in the picker, not the
inference stack. That is fixed, and llama.cpp now runs with n-gram speculative decoding, which is
a free speed-up on the same hardware.

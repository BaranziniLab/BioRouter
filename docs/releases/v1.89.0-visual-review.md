# v1.89.0 visual review of the desktop GUI

> **What this is.** The findings from a screenshot-by-screenshot look at the shipped desktop
> interface after the Astryx rebuild and the privacy-tiers merge — the class of failure that
> has no automated coverage, because jsdom has no layout engine and never runs Tailwind.
> **Status:** Current — findings from a pass on `main` at `f3533776` (2026-08-07), not yet triaged.
> **Audience:** Anyone deciding whether this build is fit to ship, and whoever fixes the rows below.

This release rebuilt the interface on a new design system and added privacy badges, banners
and modals across many existing surfaces. Both changes can fail by *looking* wrong while every
test passes. This pass drove the real Electron renderer over CDP against a sandboxed config
root, took screenshots, and looked at them; DOM measurements were used only to explain what a
screenshot already showed. Each row below says which it is: a **defect** (something is
measurably broken or unreadable) or a **taste** item (it works, it is inelegant).

Fourteen defects and nine taste items. Nothing found here corrupts data or blocks a workflow;
two make information illegible, one makes a whole panel unreadable in dark mode.

## How this was driven

Launched per [launching the dev GUI](../desktop-ui/launching-the-dev-gui.md) — direct Electron
against `.vite/build/main.js`, `env -u ELECTRON_RUN_AS_NODE`, Vite on 5173 with
`--config vite.renderer.config.mts`, `BIOROUTER_NO_HMR=1`, CDP on 9444. The port in
`MAIN_WINDOW_VITE_DEV_SERVER_URL` is baked into the main bundle, so the renderer **must** be on
5173; a different port yields `ERR_CONNECTION_REFUSED` and a blank window, which is a sixth way
to misread the launcher as a broken app.

Config was sandboxed with `BIOROUTER_PATH_ROOT` pointed at a throwaway root seeded with a copy
of the real `config.yaml`, `sessions.db`, knowledge bases and skills, with the stdio extensions
disabled. The user's installed app was never touched. Default viewport 1440×960; stress passes
at 640, 720, 900 and 1920.

Screenshots referenced below live under
`/private/tmp/claude-501/-Users-wgu-Desktop-BioRouter/967f3aca-dbfd-4952-92bf-aa0c7172ee47/scratchpad/vr/`
(session scratchpad — copy anything you want to keep).

## Defects

### D1 — Billed-token counts overflow their column and paint over the next icon

Chat history. `SessionListView.tsx:460` puts the billed-token figure in a fixed
`w-12 text-right` box — 48px. `29,988,671` measures 72px (`scrollWidth` 72 against
`clientWidth` 48), so the last digits are drawn on top of the puzzle icon that follows. The
result is an illegible glyph mash on every row that has a token estimate, in every theme, at
every width, and it gets worse as the window narrows.

The surrounding comment states the intent — "fixed-width boxes so the counts form real columns
down the list" — so the mechanism is deliberate and only the width is wrong. Two neighbours are
latent instances of the same bug: `w-8` (32px) for `message_count` overflows at five digits and
`w-4` (16px) for the extension count overflows at three.

`vr/11-history-overlap.png` (cropped, unambiguous), `vr/PL-sessions.png`,
`themes/parchment-dark-sessions.png`, `vr/narrow-640-sessions.png`.

### D2 — Knowledge-graph labels are invisible in every dark theme

`ForceGraphCanvas.tsx:249` sets `ctx.fillStyle = '#1f242c'` — a hardcoded near-black — before
drawing every node label. In Parchment dark and Alma Mater dark the graph canvas is near-black
too, so the labels vanish; the panel becomes a set of unlabelled coloured dots. This is the
worst-looking thing in the release.

The same file already re-reads its font family whenever `class` or `data-theme` changes on the
root (lines 66–82), so the theme plumbing exists and the ink was simply left out of it.

`themes/parchment-dark-knowledge.png` and `themes/alma-mater-dark-knowledge.png` against
`vr/PL-knowledge.png`.

### D3 — Tool-call rows truncate their status suffix mid-phrase, or drop it

In `ToolCallWithResponse.tsx:955–973` the status suffix (`· 1 result ready`) is a child of the
same `min-w-0 flex-1 truncate` span as the command summary, so one ellipsis budget covers both.
On a transcript of shell calls the consecutive rows read `· 1 …`, `· 1 result rea…`, and — where
the command is longest — nothing at all, while the chevron survives. Measured: the suffix span's
right edge sits at 1302.4 against a clipper ending at 1194.

The fix is structural: the summary truncates, the suffix does not.

`vr/06-chat-top.png`.

### D4 — "Show subagent runs" is a raw, unstyled native checkbox

`SessionListView.tsx:1179`. `className` is empty; computed `appearance: auto`,
`accent-color: auto`. It renders as the macOS system blue in light mode and as a bare white
square in dark. It is the only unstyled form control found anywhere in the sweep, and it sits on
a top-level list view directly under the page title.

`vr/13-checkbox-zoom.png`, `themes/parchment-dark-sessions.png`.

### D5 — The extension-failure toast never dismisses and hides header controls

The "N of M extensions loaded" toast stays up indefinitely — it was still on screen twenty
minutes after launch. At 1440px it occupies x 1144–1424, y 40–155, which is exactly where page
headers put their right-hand action. On Chat history it completely hides the **Import Session**
button; on Extensions, Applications and Knowledge it truncates the page description. It also
grows leftward as the failure list grows, so it covers more as things get worse.

Compare `vr/PL-sessions.png` (button invisible) with `vr/12-history-subagents.png` (same view,
toast dismissed, button present).

### D6 — The toast z-index token is dead

`main.css:432` declares `--z-toast: 600` as part of the "one toast tier" work. Its only
consumers are `UsageHeatmap.tsx:214` and a comment in `Select.tsx`. The real toast container
computes `z-index: 9999`, inherited from react-toastify's own `--toastify-z-index`, which is
never overridden. So the shipped stacking order is not the declared one, and the heatmap
tooltip — the one element that *does* use `--z-toast` — sits below any actual toast.

### D7 — Settings → Privacy opens on an unbound pronoun

The pane's first words are "It is not HIPAA-compliant, is not hosted on-premise…". In the modal
this prose follows a heading that names the subject ("Azure OpenAI is not hosted by your
institution."); the settings pane reuses the paragraphs without the heading, so "It" refers to
nothing on the page. The banner is also the only boxed element in the pane, above an unboxed
setting row, and it is the pane's only content besides one toggle.

`vr/20-settings-Privacy.png`.

### D8 — The disclosure modal reports a save failure in its quietest voice

When the acknowledgement cannot be recorded, the modal appends a paragraph in
`text-text-muted` (rgb 99, 92, 84) — lower contrast than the explanatory body above it — with no
icon, no colour and no separation, and relabels the button from "I understand" to "Continue".
A failure notice rendered less prominently than the prose it follows will be read as more
boilerplate.

`vr/04-chat-transcript.png`.

**How this was reached, which may itself be a bug worth checking.** The daemon this session
spawned logged `no user-action key on stdin`, so every privacy-capability raise was refused and
the acknowledgement could never be written — which is why the modal reappeared on every session
open. `main.ts` does compute a key and `biorouterd.ts:403` does write its digest, so either the
dev path drops it or the daemon's bounded stdin read loses the race. Not a visual finding, but
it should be confirmed against `just run-dev` and the packaged app before release.

### D9 — Tooltips are off the radius ladder, and pure black in the default theme

`ui/tooltip.tsx:21` uses `rounded-inner` — 4px, the role `main.css:49` reserves for "inline
code, chips, checkbox, swatches — nested inside a control". A tooltip is a popover, and
`--radius-container` (12px) is the role that names popovers. Two steps off, against the repo's
own written ladder.

Separately, `--background-inverse` in Parchment **light** is `var(--color-black)` = `#000000`,
while Alma Mater light uses `#052049` and Roche Limit light `#1f1e1c`. The default theme is the
only family whose tooltip ink was never tinted, so a pure-black chip appears in an otherwise
warm palette.

`vr/19-tabstrip-blackbox.png`.

### D10 — Group-header dots use an info blue that is off-palette

On Skills, the "BIOROUTER SKILLS (4)" marker is `bg-background-info` = rgb(30, 95, 191) while
its sibling "SKILLS FROM OTHER AGENTS (1)" marker is `bg-background-strong` = rgb(212, 202, 182).
Two dots in the same decorative role, with different semantics and wildly different weight, and
the blue is the only saturated blue on the page.

`vr/14-skills-rows-zoom.png`.

### D11 — The composer's model chip truncates at 80px beside 300px of empty row

The model name renders in an 80px span, so `gpt-5.5-2026-04-24` becomes `gpt-5.5-202…` — a
truncation that keeps only the part every model shares. The footer row's rightmost item ends at
x=966 inside a composer 1219px wide, so roughly 250px sits unused immediately to its right.
Knowledge's model row does the same thing ("Versa API Azure /…").

`vr/10-composer-zoom.png`.

### D12 — Timestamps wrap mid-value at narrow widths

At 640px the Chat-history rows break "3:18 / AM" and "08/06/2026 10:14 / PM" across two lines.
Rows that wrap and rows that do not then have different heights in the same list, so the list
loses its rhythm exactly where it is most cramped.

`vr/narrow-640-sessions.png`.

### D13 — Collapsing the sidebar leaves no rail at all

The sidebar is `data-collapsible="offcanvas"` and collapses to width 0 — there is no icon rail.
On a non-chat route (Applications, Settings, Knowledge) the toggle button is then the *only*
control left on screen: Home, New Session, Recents and Settings are all unreachable until it is
re-expanded. On a chat route the tab strip softens this, elsewhere it does not.

This may be the intended behaviour of `offcanvas` rather than a regression, but it sits badly
with the "compact the rail" framing of the Astryx sidebar work, and it is listed here so the
decision is made deliberately rather than inherited.

`vr/22-sidebar-collapsed.png`.

### D14 — The composer placeholder is a hint about messages that do not exist

`ChatInput.tsx:1824` sets `placeholder={getNavigationShortcutText()}` → "⌘↑/⌘↓ to navigate
messages". On Home and on a brand-new session there are no messages to navigate, so the primary
input of the application invites nothing and explains a shortcut that does nothing yet.

`vr/01-home-parchment-light.png`.

## Taste

- **T1 — The chip vocabulary is not unified.** Four formats coexist within two adjacent rows:
  `BUILT-IN` is a bordered uppercase pill, `Public`/`Private` are borderless text (one with a
  shield icon, one without), `Paused` is a filled pill with an icon, and
  `Recommended`/`Needs download` are tinted pills. Visible together on Extensions, Scheduler and
  Skills. `vr/PL-extensions.png`, `vr/PL-schedules.png`.
- **T2 — Home has about 360px of dead vertical space** between the bottom of the heatmap and the
  composer, with nothing in it. `vr/01-home-parchment-light.png`.
- **T3 — Ghost and filled buttons share a right-aligned column** in Settings → Models. The boxes
  align exactly (all right edges at 1356), but a filled `Install` paints to 1356 while a text-only
  `Delete` stops at 1348, so the column reads ragged even though it measures true.
- **T4 — Knowledge-graph labels collide** with each other and with node circles; "ADHD-related
  neurotransmitter pathways" runs straight through the "OMOP Common Data Model" node.
  `vr/PL-knowledge.png`.
- **T5 — Settings → Privacy is ~80% empty** — one banner and one toggle in a full-height pane.
- **T6 — The sidebar Recents list clips its last row mid-glyph** with no fade or mask, so a
  half-height word sits above the divider. Visible in every theme.
- **T7 — The composer cost reads "Unavailable"** in monospace where Home shows `$0.00`. An
  error-shaped word in the numeric slot, with no explanation of what is unavailable or why.
- **T8 — Inline code chips break mid-token** at narrow widths (`drug_exp` / `osure`), splitting
  the chip background across two lines. The alternative is horizontal overflow, so this is a
  defensible trade, but it looks broken. `vr/narrow-640-chat.png`.
- **T9 — The selected radio row in Settings → Chat** has an 8px-rounded tint whose bottom
  corners meet a straight 1px separator running the full width. `vr/26-settings-chat.png`.

## What held up

Worth recording, because these are the failure modes this repo has had before and they did not
recur:

- **No horizontal page scroll and no clipped content** on any route at 1440px, and none at 900,
  720 or 640 either. The `min-w-0` discipline is holding.
- **Pathological names truncate cleanly.** A 180-character session title, a 130-character
  no-space string and a full query URL all ellipsised correctly in both the sidebar and the
  history list, with no bleeding. `vr/16-longnames-sessions.png`.
- **Dark-mode chips are properly re-toned**, not light chips pasted onto a dark ground —
  `bg-background-success/15` over the dark surface with a light-green ink. `vr/15-dark-chips-zoom.png`.
- **Modals size correctly at both extremes** — `max-w-[560px]` with a `calc(100% - 2rem)` floor,
  verified at 640px and 1920px.
- **Dialog padding is uniform** at 24px on all four sides, and the modal surface matches
  `--background-card` rather than inventing its own.

## What was not checked, and why

- **The artifact side panel.** It needs a live turn that produces an artifact. This pass was
  deliberately model-free apart from what the app did on its own, so the panel was never
  populated.
- **Nested subagent runs in History.** "Show subagent runs" works, but the sandboxed session
  database contained none, so the nested presentation never rendered.
- **Two of the six theme combinations.** Parchment light, Parchment dark, Alma Mater dark and
  Roche Limit light were swept; Alma Mater light and Roche Limit dark were not. The two defects
  that are theme-dependent (D2, D9) were both confirmed against a dark theme and against the
  default light theme respectively.
- **Dialogs other than the non-private-model disclosure** — rename, delete confirmation, the
  extension modal, `BrxtInstallModal`. All now come from one shell, so the disclosure modal's
  geometry is evidence about them, but that is inference, not observation.
- **The Knowledge change-log drawer and the Workflows route** were captured but not analysed
  in depth.
- **Toasts other than the extension-failure one.** Only the one the app raised by itself was
  seen, so D5 and D6 are about that instance.

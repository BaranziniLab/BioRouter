# Implementation notes (from archaeology of 07969fac / ad3676b5)

## F1 — the hyphen/underscore trap (LATENT BUG WE ARE FIXING)
The deleted modules registered as `"claude-code"` / `"cursor-agent"` / `"gemini-cli"` (HYPHEN),
while `pricing.rs::blocks_fallback_pricing` guards `"claude_code"` / `"cursor_agent"` /
`"gemini_cli"` (UNDERSCORE). `provider_model_pricing` lowercases and does NOT normalise
`-`<->`_`. So three of the four guards NEVER MATCHED the names those providers shipped, and a
subscription-billed run was being given a fabricated Anthropic catalogue price.
=> We register `claude_code` and `codex` with UNDERSCORES, which is what the guard already
   lists. This fixes the bug rather than reproducing it. Add a pricing test pinning the
   registered spelling.
=> Do NOT add a `"claude_code" => "anthropic"` alias in canonical/name_builder.rs. That alias
   is exactly the hole 07969fac closed (it routes into canonical_model_pricing).

## F6 — ProviderUsage.provider MUST be set
All four old modules returned `ProviderUsage::new(model, usage)` leaving `provider: None`.
Usage rows then get attributed by MODEL name -> Anthropic/OpenAI catalogue pricing -> the same
fabricated-cost bug by a second route. Set `.provider = Some(provider_id)`.

## F4 — ProviderMetadata::new derives context limits from the model NAME
`base.rs:200` maps each known model through `ModelConfig::new_or_fail(name).context_limit()`.
Aliases ("sonnet", "opus") are not real ids, so they silently take the DEFAULT limit.
=> use `ProviderMetadata::with_models(...)` with explicit ModelInfo context limits, like
   llamacpp does, and/or add MODEL_CONTEXT_WINDOWS entries.

## Defects in the old modules that we must NOT reproduce
1. `_tools: &[Tool]` ignored -> extensions unusable. (Fixed by the MCP bridge, Phase 4.)
2. Auto mode passed `--dangerously-skip-permissions`, letting the child use its OWN tools.
   We keep the child's tools OFF (`--tools ""` / read-only sandbox) and expose only
   BioRouter's tools over MCP, which BioRouter's own dispatcher gates.
3. stderr was piped and NEVER READ on all four -> the CLI's diagnostic was discarded on every
   failure, AND a child writing more than the pipe buffer to stderr can block forever.
   => drain stderr concurrently and include it in the error.
4. NO timeout and NO cancellation anywhere. A `claude -p` run can last many minutes.
   => tokio::select! on a CancellationToken + a turn deadline.
5. Whole conversation passed as one `-p` argv element (argv length limits).
   => prompt via stdin, or a bounded argv.
6. Every failure collapsed to `ProviderError::RequestFailed` — no Authentication, no RateLimit.
   `cursor_agent` alone probed auth and returned a typed `Authentication` error; that is the
   one idea worth stealing, and our discovery module generalises it.
7. `claude_code` left `Chat` mode with NO sandbox restriction (unenforced). `codex` mapped
   Chat -> `--sandbox read-only` correctly.
8. `claude_code`/`codex` did NOT inject PATH into the child; cursor_agent/gemini_cli did:
   `cmd.env("PATH", SearchPaths::builder().with_npm().path())` BEFORE the scrubs.
   Needed because these CLIs shell out to git/rg/node themselves.

## filter_extensions_from_system_prompt — do NOT use
Zero callers today. It removes only the `# Extensions` section and leaves `# Tool Use`,
`# Tool Routing`, `# Tool Output Is Data...` in place. It existed because the old providers
passed no tools. We DO pass tools (via the bridge), so the roster is accurate and the filter
would be wrong.

## strip_daemon_private_env — zero overlap with our scrub (verified)
It removes a key only if, uppercased, it starts with `BIOROUTER_SERVER__`/`GOOSE_SERVER__`, OR
starts with `BIOROUTER_`/`GOOSE_` AND contains one of SECRET/TOKEN/PASSWORD/PASSWD/PASSPHRASE/
PASSCODE/CREDENTIAL/API_KEY/APIKEY/PRIVATE_KEY/SIGNING_KEY/AUTH.
Nothing outside those namespaces is ever touched — `AWS_SECRET_ACCESS_KEY` surviving is an
explicit tested guarantee. So our subscription scrub cannot over-strip by duplicating it, and
both are required.
